# Benchmarks

This page reports the default solver (`bs.solve`) broken down **by difficulty**,
so the easy and the hard regimes are both visible rather than hidden behind a
single average. The headline preset numbers and the 10,000-case aggregate are in
the [README](../README.md#regression-and-benchmark); this page is the
audit-oriented breakdown.

## Difficulty grid

Generated by [`benchmarks/difficulty_buckets.py`](../benchmarks/difficulty_buckets.py).

**Methodology** (so the numbers can be reproduced and audited):

- Solver: `bs.solve`, `precise` preset, `dt = 0.004`, `tolMiss = 1e-2`.
- `tMax`: `8.5 s` for low arc, `20.0 s` for high arc (plunging shots fly longer).
- Cases: constant-velocity moving targets, **reachable by construction** — each
  case is built by simulating a real shot and placing a moving target on it, so a
  sub-100% success rate would reflect the solver, not an impossible target.
- High-arc cases draw the intercept time **after apex** (`apex+0.5 … apex+8 s`),
  so the projectile is genuinely *descending* onto the target — a plunging shot,
  not a steep direct-fire shot that the low branch would also solve.
- Success: `result["success"]` (miss ≤ `tolMiss`).
- Timing: per-call `time.perf_counter` on the native extension after warm-up.
- Seed: fixed (`20260601`), 1,500 cases per bucket. The case set is therefore
  deterministic; `--dump cases.json` writes it out for external re-runs.

## How to read it

- **Success is 100% in every bucket**, including the hardest one (high-arc,
  heavy-drag, plunging). Accuracy (P95 miss) sits well inside `tolMiss`
  everywhere, and is at machine precision for the drag-free cases, where the
  vacuum solution is exact.
- **Cost scales with difficulty.** Drag-free solves are sub-millisecond. Low-arc
  direct fire with drag is ~0.3 ms median. The expensive corner is high-arc
  plunging *with* drag: a ~1–2 ms median and a long tail
  (heavy-drag P99 ≈ 31 ms) where the multistart fallback does the most work. That
  tail is the genuine worst case and is shown rather than averaged away — if your
  use case is real-time and high-arc with strong drag, budget for it.

## Reproducing

```bash
python benchmarks/difficulty_buckets.py
python benchmarks/difficulty_buckets.py --dump cases.json   # also export the fixed case set
```

Other benchmark scripts:

- `benchmarks/linear_cases.py` — preset (fast/balanced/precise) timing on linear cases.
- `benchmarks/intercept_eval.py` — end-to-end tracker-vs-baseline realism check across domains.
- `benchmarks/predictor_eval.py` — lead-prediction accuracy of the tracker vs a constant-velocity baseline.
